to build, ship and run containers, we need a container runtime engine be installed on the hosts operating system.
1. The engine shares the HOST'S OS kernel among the containers
2.Contanerized Application are "isolated"
Docker is the most popular container engine 


Starting with a Dockerfile , we can build a container image that can be used to consistently run a application across different environments.

Docker File -----> (docker build) ----> Docker Image -----> (docker run) ----> container

Docker is a software platform that simplifies the process of building , running and dstributing applications using containers.

Docker Architecture - Docker Client 
It enables developers/users to interact with Dockers 
When you use docker commands , the docker client sends these commands to the Docker daemon(dockerd)
client cli >>>>>
> docker pull 
> docker run 
> docker build

Host Architecture 
The server or Virtual machine on which Docker Engine is installed
The docker Daemion (dockerd) id the heart of docker

Docker Images
Images are read only binary templates used to build containers 

Docker Daemon Architecture
The Docker Daemon (dockerd)  id the heart of Docker 
--> It listens to the Docker API requests (from the Docker client) and manages containers , images ,networks and volumes
--> it build container images as requested by the client
--> it interfaces with docker registries to pull or publish images as requested by the client 

Docker Registries
A docker registry stoes Docker images
Docker Hub is the public registry that anyone can use 
when needed the required images can be pulled from the configured registry 
users can push their created images to the configured registry

Understanding how Docker Works
Docker CLI 
--> Docker CLI communicates with the Docker Daemon/server, dockerd

Dockerd
--> dockerd processes the Docker API requests and utilizes containerd functionality to manage the container's life cycle

Containerd
Manages containers, storages and Networking 
Pushes and pulls images
